# Cine

Opinionated UI for WoW Forever. Modern and cinematic: few frames, few buttons, text stays. The addon turns on or off, and one window chooses what stays visible.

## Product

- The goal is a clean UI, not a configurable framework.
- `/cine` turns it on or off (`on` / `off`, no argument toggles). `/cine setup` is the one window, with seven tabs: General, Visible, Bars, Groups, Player, Chat, and Info. Info holds a short description of Cine and how Glance works. General holds shared presets and their existing Edit Mode layouts, or Force Cine layout for <no preset> (missing means off). Check what stays visible, set which bars fade together, choose which bars stay up for an enemy or a friendly target, turn the player frame on or off, group buffs and debuffs with that frame (missing means on), keep debuffs always visible (missing means on), turn In range on or off, choose 10 yards, 28 yards, or Spell, type an optional spell name, and choose Unfriendly or Friendly, choose modern chat and how soon its lines fade, then Save, which leaves the window open. Reset default restores the rules below, turns force off, and saves immediately. Import layout writes the bundled Edit Mode layout right away, even after "Not now". The X and Escape close the window without saving. The window stays the size of the tallest tab, so switching tabs does not resize it. A minimap button opens that window. Left click opens it even while Cine is off. Drag moves it around the minimap.
- `CineDB` is the account and may hold only `enabled`, `layoutHash` (the last answered layout version), `presets` (stable IDs to named shared settings and layout references), `nextPresetId` (monotonic ID counter), and `minimap` (degrees around the minimap for the setup button; a missing value sits at the bottom-left). The setup is per character in `CineCharDB`: `presetId` (missing means <no preset>), `previousLayoutRef` (name and type, or built-in identity, for restoring after layout reordering), `presetLayoutManaged` (a preset took over the layout; restore it even after detaching), and a personal snapshot of the settings: `visible` (HUD rows that stay on screen; excludes action bars and swing timer; a missing flag means off), `hoverOnly` (HUD rows that show only on hover; missing means on for XP, quest tracker, damage meter, micro menu and raid manager unless Always visible is set, and off for the rest; explicit false keeps the usual rules), `groupVisibility` (numeric fade-group IDs to `"always"`, `"hover"` or `"usual"`; missing means usual rules, except group 2, which defaults to `"hover"`), `forceLayout` (`true` selects the Cine layout when the addon turns on and restores the previous one when it turns off; missing means off), `player` (`resource` keeps the portrait for edit mode; missing means on, beside the personal resource bar), `playerThresholdKind` (`"health"` or `"resource"`; missing means health) and `playerThresholdPercent` (whole percentage 1–100; missing means 70, `false` ignores the trigger), `requireLivingTarget` (`true` hides player, pet, and target frames for a dead or ghost target outside edit mode; missing means off), `groupAuras` (`false` leaves buffs and debuffs on their own; missing means on), `alwaysShowDebuffs` (`false` lets debuffs follow the usual aura fade rules; missing means on), `chat` (`false` turns modern chat off; missing means on), `letterbox` (`false` turns the cinematic bars off; missing means on), `combatZoom` (`false` stops the combat distance; missing means on), `combatZoomPercent` (whole 1–100, share of the farthest zoom; missing means 60), `defaultZoom` (`false` turns the default distance off; missing means on), `defaultZoomPercent` (whole 1–100; missing means 30) and `rememberZoom` (`false` returns to the default distance after combat, when that is on; missing means the previous distance), `chatFade` (seconds a modern-chat line stays at the bottom; missing means 10, `0` keeps it), `groups` (fade group per bar; a missing key keeps the default below), `hostile` and `friendly` (bar ids that stay up while the target is alive and can be attacked, or is friendly; a missing key means off, except `hostile` bars 1 to 3, which default on; an explicit false turns a default off), `range` (`yards` is `10`, `28`, or `"spell"`, `kind` is `"hostile"` or `"friendly"`, and `spell` is an optional spell name; a missing `spell` means the longest matching spell on bar 1; a missing `range` means off), and `previousLayout` (the Edit Mode layout index that was active before Cine, kept even while force is off). No sliders and no libraries like Ace3.
- Presets share all setup settings except forceLayout, which is only for <no preset>. Save commits selection, creation, rename, layout and settings together. Choosing a preset layout previews it immediately, including while disabled; combat defers the switch. X/Escape cancel the preview and restore its original layout. Save keeps the preview and preserves the layout to restore on disable. Delete requires confirmation and is immediate. Missing/deleted presets detach to the last personal snapshot. Reset detaches and saves defaults without changing the shared preset. A preset selects its linked layout on login, enable and Save; missing layouts fall back to Cine with one warning per session and retain the invalid link for repair. Disable restores the previous layout.
- Player-facing text (chat, tooltip) is English.

## Look

- Flat, dark, thin border. Background `0.05, 0.05, 0.05, 0.75`, border `0.85, 0.85, 0.85, 0.35`, highlight `0.95, 0.75, 0.25`.
- The setup window uses the game character frame: gold border, player portrait, and the game's checkboxes and buttons. When that frame template is missing, it uses the gold dialog, then the flat border.
- Message prefix: `|cff8fd4c8Cine|r`.
- A short friendly greeting on login and reload: the state, then one short line each for `/cine` and `/cine setup` so commands never wrap. No other chat messages unless the player acts or something fails.
- Visible has mutually exclusive Always visible and Only on hover checks per HUD row; action bars and swing timer are configured only in Bars and Groups. Bars holds per-bar Enemy, Friend and Group. Groups holds a scrollable Group visibility section with one row per used group, its members, and mutually exclusive Always visible and Only on hover checks. The setup window is compact and keeps one height across tabs. General selectors span its content width and its preset buttons are evenly spaced. With both checks off, the usual rules apply. Group modes disable Enemy/Friend without clearing their values. Only on hover overrides combat, vehicle, instance, group, target, low health/power, XP reward and post-combat timer rules. It also overrides aura grouping and Always show debuffs. Glance and Edit Mode still reveal these frames; bars and XP also show with an open spell flyout or an item on the cursor. An item on the cursor shows the bag bar. Cooldowns, meter and resource gain independent hover catchers on UIParent; disable hides these and restores alpha. Settings share through presets; Reset clears custom modes and restores the defaults: Only on hover for XP, quest tracker, damage meter, micro menu and raid manager, bar group 2 on Only on hover, and Enemy on for bars 1 to 3. Legacy visible.bars and visible.swing pins migrate to group modes, splitting mixed groups to preserve visibility. A checked row under Always visible stays visible and skips the fade below. Unchecked rows keep it. The player frame check turns the portrait and pet on beside the resource bar, and they still fade.
- Action bars fade in groups. A faded frame appears at once and fades out over 0.3 s. Hover shows the whole group from the bar rectangle, including empty slots. A filled button stays above that rectangle, so its tooltip and click still land on the spell. The default is bars 1–3 with the stance bar, the pet bar and the totem bar, bars 4–5, and each later bar on its own. The swing timer is group 10. The same number in `/cine setup` fades together. Combat, a vehicle, edit mode, an instance (party, raid, pvp, arena), an open spell flyout, or an item on the cursor shows every group. Always visible in Group visibility keeps the entire selected group up, including the swing timer if it belongs to that group. Only on hover uses hover of any member to reveal the entire group. Enemy and Friend on a bar row keep that bar up while the target is alive and can be attacked (`UnitCanAttack`, and not `UnitIsDeadOrGhost`) or is friendly (`UnitIsFriend`), including out of combat. They do not show the rest of the fade group. A missing flag means off. The XP bar defaults to Only on hover like those other rows, with Glance, Edit Mode, spell flyout and cursor-item exceptions. Unchecking Only on hover restores the usual bar triggers: combat, a vehicle, an instance, hover, Edit Mode, flyout and cursor items, plus 5 s after a quest turn-in that gives XP. Always visible keeps it up.
- The cooldown manager shows only in combat, in an instance, in a group, or in edit mode. Hover does not show it.
- The damage meter behaves the same and stays for 10 s after combat.
- The personal resource bar shows only in combat, in an instance, or in edit mode, and anywhere while mana, focus, or energy is below 70 %. Its health bar also shows anywhere while health is not full. Hover does not show it. It appears at once and fades out over 0.3 s. While the player frame is on, the Personal resource row is not Only on hover, and a dead target is not hiding the player frame, the bar is linked to the player frame: they show and hide together, the way grouped buffs follow the player frame. The bar then takes the player frame's triggers (a target, a group with Always show player frame in party on, a vehicle, hovering the player frame or pet, and its threshold alpha) as well as its own combat, instance, Edit Mode, Glance and Always visible triggers, and its separate power and health rules do not apply. Always visible on the Personal resource row therefore keeps the player frame up too. With the player frame off, Only on hover, or a dead target hiding the player frame, the bar keeps its own rules.
- The player frame (`PlayerFrame`) is on unless setup sets `player` to `resource`. Off, it shows only in edit mode. On, it shows with a target, in combat, in an instance (party, raid, pvp, arena), in a group when Always show player frame in party is on (off by default), in a vehicle, while eating or drinking (a Food, Drink, Food & Drink or Refreshment buff, read out of combat), on hover, and while Glance is on. It also shows below one selected threshold: Health or Resource (mana, focus or energy), default Health below 70%. An empty Percent input ignores this trigger; the threshold does not restrict combat, instance or the other usual show rules. The selector and input are shown only while Player frame is on, retain their values while off, and save through presets. Percentages must be whole numbers from 1 to 100; exactly at the threshold does not trigger visibility. Rage and the other powers that rest at zero do not. A pet being out does not keep it up. `PetFrame` uses the same alpha. It appears at once and fades out over 0.3 s. The personal resource bar is linked to it as described above. While the player is dead or a ghost the portrait fades on its own, overriding the usual triggers and the threshold; this adds no setting. A target, Glance and Edit Mode still show it, Player frame off keeps its rule, and the pet and auras keep their usual behavior (a pet under the portrait ignores the inherited alpha through `SetIgnoreParentAlpha`; when the client cannot, the portrait and pet keep the usual rules). Player setup also offers Require a living target (default off). When on, a dead or ghost target fades the player, pet, and target frames even in combat, on hover, or with a low threshold. Glance and Edit mode still show them. With a living target, no target, or the option off, the usual rules apply and Blizzard controls the target frame.
- In range is off unless setup checks it. Checked, a green gradient fills the health bar on the target's nameplate while that target is alive and in range. It is strong on the left (`0.15, 0.82, 0.22` at `0.9`) and fades toward the right (`0.55, 0.95, 0.4` at `0.15`), so the bar still shows through. It is drawn only while the action bars are down. Combat, a vehicle, an instance, Edit Mode, an open spell flyout, an item on the cursor, Glance, and any action bar group under Always visible skip it, and the distance is not read in those cases. It does not show action bars. The plate comes from `C_NamePlate.GetNamePlateForUnit("target")` (or `GetNamePlateForUnit`). The gradient prefers the short health bar inside the plate, not the tall click area, and is parented to that bar, because a nameplate has no screen rectangle to copy. When the gradient hides it returns to `UIParent`. The nameplate's alpha is never changed. Within is 10 yards (`CheckInteractDistance` trade), 28 yards (inspect), or Spell. Spell uses `IsSpellInRange` on the name in the Spell field. An empty Spell field uses the longest harmful or helpful spell on bar 1, read with `IsActionInRange`. Unfriendly keeps a harmful spell, so a neutral the spell can hit still counts when `UnitCanAttack` is false. Friendly keeps a helpful spell and a reaction of 5 or higher. A dead target does not count. Only `target`. With no nameplate on screen the gradient stays down. It appears at once and fades out over 0.3 s. The distance is read every frame, so walking into range does not wait on focus. Glance, combat, and Always visible do not turn it on. A missing `range` means off. A secret range result is left as it was.
- The quest tracker (`ObjectiveTrackerFrame` / `QuestWatchFrame`) shows only on hover or in edit mode. Hover is the whole rectangle, including the gaps between quests. An invisible catcher on `UIParent` follows that rectangle. It is not a child of the tracker, so a faded tracker does not drop the mouse, and it does not take clicks. It appears at once and fades out over 0.3 s.
- Debuffs (`DebuffFrame`) always stay visible while Cine is enabled unless Player setup unchecks Always show debuffs (`alwaysShowDebuffs`, missing means on). This overrides aura grouping and player frame visibility without revealing buffs or the portrait. With this option off, they follow the same rules as buffs below.
- Ignored debuffs (a short built-in list in `Features/Faders/Ignored.lua`, currently Boosted Rest) show only by the usual aura rules (combat, an instance, a group, hover, Glance, Edit Mode, or the player frame with grouping), not through Always show debuffs: their icons fade like the other aura frames, so the others keep their places. Names are read out of combat only; disable restores them.
- Buffs and optional fading debuffs (`BuffFrame`, `DebuffFrame`, `TemporaryEnchantFrame`) also show for 5 s after a new buff arrives out of combat (a refresh or a full update does not count; Only on hover overrides it; ignored debuffs stay hidden unless the usual rules below show them), and otherwise show only in combat, in an instance, in a group, on hover, or in edit mode. With `groupAuras` on they also show while the player frame is visible, including its selected health or resource trigger while the player frame is on. With the player frame off, grouping does not pull them up. They appear at once and fade out over 0.3 s. While the player is dead or a ghost the buffs (`BuffFrame`, `TemporaryEnchantFrame`) fade out whatever else would show them, including a new buff and the player frame; hover on them, Glance, Edit Mode and Only on hover still apply, and debuffs keep their own rules; this adds no setting.
- The native bag bar (backpack, bag slots and expand toggle) stays beside the micro menu and fades with it, using the micro menu row's rules. An item on the cursor shows it until the item is dropped. Cine never hides individual bag slots.
- The micro menu and the bag bar show on hover (the whole row, including the gaps, or any bag button), in edit mode, or while Glance is on. It appears at once and fades out over 0.3 s. A checked row under Always visible holds it. Combat, an instance, and a group do not show it.
- Press `` ` `` (Glance) to show the faded HUD at once: every action bar, the XP bar, the cooldown manager, the damage meter, the personal resource bar (health and power), the quest tracker, buffs and debuffs, and the micro menu with the bag bar. The portrait and pet show only when the player frame is on. Press again and the rules above apply, including a checked row. The state is not saved, and turning Cine off clears it. Chat is unchanged and the addon does not toggle. The binding is `CINE_GLANCE`, category `CINE` (shown as Cine). Do not set `header` on it: the client turns that into a bindable row named `HEADER_CINE` under Other. `SetBinding` applies `` ` `` when that key is free or still on `HEADER_CINE`, and leaves any other action alone. The key can be changed in Key Bindings. Only the key-down arrives as a toggle; key-up is ignored.
- The addon ships an Edit Mode layout named `Cine`. `Layout/String.lua` is the source of truth. Each new version of the string is offered once in the addon's own prompt. It uses the same character frame as setup, with a gear icon instead of the player portrait (the flat border when that template is missing; not `StaticPopup`, which spreads taint). The answer (add, update, or not now) is remembered as a hash in `CineDB.layoutHash`; saved layouts are never compared, because the client rewrites them. An updated layout is replaced in place only after the player agrees. With Force Cine layout on, turning Cine on selects the Cine layout and creates it from that string when it is missing. The layout that was active before is stored per character as `previousLayout` and selected again when Cine is turned off. With no preset and force off, enable, disable, login, and reload leave the active layout alone. An active preset uses its existing layout instead of forcing Cine; when its layout is missing the bundled layout is created only if needed. Use `C_EditMode` only, never `EditModeManagerFrame` methods (taint).
- Letterbox is on unless the Visible tab unchecks it. Unchecked means off. On and Cine on, two black bars slide in (0.6 s, eased) at the top and bottom of the screen. Each bar is half of what a 2.39:1 frame leaves over (none on a screen already that wide or wider). They stay up always, but shrink to half that height in combat, while Glance is on, or while fade group 1 shows (a group 1 bar on screen and kept up), and slide back when that ends. They sit in `BACKGROUND` strata under the UI, never take the mouse, and follow resolution and UI scale changes. Disable or unchecking slides them out and hides them. It is a shared preset setting.
- Chat keeps its text and drops the chrome while Modern chat is on (the default). Each line is a translucent black bubble; a new line slides in from the left and older lines ease upward. At the bottom, a line fades across its last half second and drops after the fade interval (10 s unless setup says otherwise; 0 keeps it). The lines stay in the list, so scrolling still walks the full history. Hovering the chat block shows the lines that fit in the window, including ones that already faded, and the wheel works on that whole block. Leaving it fades back to the bottom view. Hover a line to copy it; only the message text is copied, without the time, channel tag or sender name (lines without a sender keep their text minus time and channel tag). A numbered channel shows only its number, and guild, party, raid and the other group tags use a short letter. Joining, leaving, or changing a channel is not shown. Money and experience follow the chat tab filters (Experience and Currency). Loot stays. The input is a flat field, visible at once while focused, and it fades out when it loses focus; while unfocused it does not take clicks, so they reach the tabs. Enter stays a Blizzard binding. The chat tabs keep Blizzard's own points above the chat and are never moved. They are hidden until the mouse is over the chat or the tab row. The tab row counts as hovering its chat, so clicking a tab shows that window's lines at once; a tab that flashes for new messages stays visible on its own. Whisper tabs that open their own temporary window get the same Modern chat treatment. A window that was hidden behind another tab has its native lines hidden again as soon as its tab is shown, and shown windows are checked a few times a second, so a custom tab such as Guild never shows the original text under the bubbles. Turning Modern chat or Cine off shows the tabs again and leaves the original chat untouched.

- Cine sets the camera with console commands (`ConsoleExec`) and nothing else about the camera is saved. **Action camera** runs `actioncam full`, `camerakeepcharactercentered 0`, `actioncam noheadmove` and `actioncam focusall`. **Normal camera** runs `actioncam off` and `camerakeepcharactercentered 1`. Action camera is the default: it is applied once at login and reload while Cine is on, together with a glide to the default distance, 30 % of the player's zoom limit unless the Default distance (General tab, Camera section, on unless unchecked, with a Percent input, whole 1 to 100) is unchecked, which leaves the login camera distance alone. The same section has a Test zoom field and button that glide to that percentage of the zoom limit, and Back (or closing the window) glides to where the camera was; the field is never saved (not on every apply, so a camera picked with the key survives Save and zone changes). One binding, `CINE_CAMERA_TOGGLE` (category `CINE`, no default key, key-up ignored), switches between the two: it goes to Normal camera when Cine last set Action camera, and to Action camera otherwise. It does nothing while Cine is off. Turning Cine off applies Normal camera if Cine had changed the camera. A missing `ConsoleExec` or a failing command is reported once through `Report`. Entering combat zooms the camera out while Cine last set Action camera (Normal camera, picked with the key, leaves the zoom alone) (General tab, Camera section, Combat distance, on unless unchecked, with a Percent input; a shared preset setting) to 60 % (the Percent input, whole 1 to 100) of the player's zoom limit (15 yards times `cameraDistanceMaxZoomFactor`), never closer in than the camera already is while Cine is on, in steps: one `CameraZoomOut` or `CameraZoomIn`, a wait for the camera to settle, then a `GetCameraZoom` read, because the calls overshoot and a step per frame piles up (leaving combat glides to the previous distance, or to the default distance when Return to my previous distance is off and the default distance is on, along a smoothstep path, correcting toward the planned point every frame; the limit is never changed).
- `/cine glance` toggles Glance through the same function as its key binding, for use in macros and controller setups. It does nothing while Cine is off, does not toggle the addon, and does not save the Glance state.
- `/cine preset` lists the current and available shared presets. `/cine preset "name"` selects an existing preset by case-insensitive name, saves its personal snapshot and applies the usual preset layout rules without changing enabled state. Combat defers the layout; while disabled, selection waits for enable. Missing or ambiguous names only print an English error. A successful selection cancels any setup draft and layout preview and refreshes the open setup window.
- The layout selector filters built-in and saved layouts by the client's `interfaceStyle` and current input interface mode. Missing style means keyboard and mouse. Named layout references include `interfaceStyle` to distinguish matching names across modes; filtering never changes the absolute Edit Mode indices.
- Shared presets hold an `interfaceStyle` tag derived from their linked layout on Save. Legacy presets derive and save the tag from layout metadata. The shared preset selector and slash list filter by the current mode, and slash commands and activation reject incompatible presets before changing settings or previews.
- Login/reload validates the selected preset's layout interface once, waiting for layout data if needed and before selecting a layout. An incompatible preset detaches to its personal snapshot without modifying the shared preset or switching the active layout. Missing layouts retain the existing fallback behavior.

## Client

- WoW Forever beta, `Interface: 16001`. The API mixes classic and newer frames; a global may not exist.
- The main bar is `MainActionBar`, not `MainMenuBar`. In gamepad mode the bars live under `GamepadMainActionBarFrame` (load-on-demand `Blizzard_GamepadActionBars`). The damage meter is a Blizzard load-on-demand addon; its frames are found by the `DamageMeter` prefix. The cooldown manager is `EssentialCooldownViewer`, `UtilityCooldownViewer`, `BuffIconCooldownViewer`, `BuffBarCooldownViewer`. The personal resource bar is `PersonalResourceDisplayFrame`; do not fade nameplates, they are recycled across units.
- Unit health and power are secret values, even out of combat. Never compare them or do math on them; pass them to widgets (for example `UnitPowerPercent` with a `C_CurveUtil` curve into `SetAlpha`). Check with `ns.IsSecret`.
- Scans of `UIParent` children can hit forbidden frames. Check `ns.Usable` before calling any method.
- Wrap calls that may be missing on this client in `pcall`, or check `type` first.
- An unknown event in `RegisterEvent` throws. Register each event separately inside `pcall`.
- Print each error once through `Report`.

## Touching the UI

- Action bars only through alpha. Do not use `Hide()`, `Show()`, or state drivers on bars.
- No secure snippets. Do not touch `ChatFrame_OpenChat`.
- `PlayerFrame` and `PetFrame` only through alpha, per the rule above. TargetFrame may only be faded through alpha for Require a living target. Do not hide party or raid frames, the minimap, vehicle / extra action / zone ability, or the LFG eye (`QueueStatus`, `LFGEye`).
- An action button never keeps `SetIgnoreParentAlpha(true)` while Cine is on: a hook undoes it, so another addon's glow on a button (Glowing Bars) fades with the bar Cine hides.
- Blizzard overwrites alpha. Hold the wanted value with a `SetAlpha` hook and the `_cineApplying` flag so the hook does not loop.
- Disabling must restore saved alpha and textures (`RestoreAll`). Wire new behavior into both `ApplyAll` and `RestoreAll`.

## Code

- Files load in `Cine.toc` order and share the addon table: `local _, ns = ...`. No globals except `CineDB`, `CineCharDB`, the slash command, `CineSetup` so Escape can close the setup window, `CineGlance`, `CineCameraToggle`, `Cine` (the minimap button frame's name), `BINDING_CATEGORY_CINE`, `BINDING_NAME_CINE_GLANCE`, and `BINDING_NAME_CINE_CAMERA_TOGGLE` for the Glance and camera keys. Do not add libraries.
  - `Core/`: `Base.lua` (`DB`, `Print`, `Report`, `Usable`, `IsSecret`), `Hover.lua` (focus tracking, `Hit`), `Alpha.lua` (alpha hooks, held values), `Fade.lua` (fade steps), `Textures.lua` (texture hiding), `Restore.lua` (`RestoreAlpha`), `Frames.lua` (bar / bag / spared classification, `Mute`), `World.lua` (combat, group, instance, target, cursor state).
  - `Settings/`: `Presets.lua` (shared preset CRUD, effective settings, personal snapshots), `Getters.lua` (`CharDB`, `Pinned`, `PlayerStyle`, `GroupAuras`, `AlwaysShowDebuffs`, `ChatFade`, `Range`, ...), `Groups.lua` (bar rows, visibility migration, fade groups).
  - `Features/Bars/`: action bars (`Frames`, `Ownership`, `Buttons`, `Catchers`, `Swing`, `Fade`), `ShowAll`, `BarTarget`.
  - `Features/Faders/`: `Discovery` (frame lookup), `Visible` (hover and group fades, `UpdateFaders`), `Curves`, `Resource`, `Player`, `Party`, `Auras`, `Quest`, `Smooth` (per-frame runner), `Range`, `RangeMark`.
  - `Features/Menu/`: `Bags.lua` (the bag bar's rules) and `Micro.lua` (the micro menu and bag bar fade).
  - `Features/Chat/`: chat chrome, line bubbles, and the input box, split into `Base`, `Input`, `Scroll`, `Lines`, `Text`, `Links`, `Copy`, `Bubbles`, `Pool`, `Layout`, `Tabs`, `Update`, `Strip`.
  - `Features/Glance/`: the Glance toggle and its key binding.
  - `Features/Letterbox/`: the letterbox bars (`ns.Letterbox`, `ns.ApplyLetterbox`, `ns.RestoreLetterbox`).
  - `Features/Camera/`: the Action and Normal camera commands, the toggle key binding, and the login default.
  - `Layout/`: `String.lua` (only the Edit Mode export string; update it by pasting a new export), `Layouts.lua`, `Preview.lua`, `Select.lua`, and `Prompt.lua` (asks to add or update the `Cine` Edit Mode layout from that string).
  - `Setup/`: the `/cine setup` window (`Style`, `Paint`, `Draft`, `Widgets`, `Window`) and the minimap button (`Minimap.lua`).
  - `Cine.lua`: `ApplyAll`, `RestoreAll`, events, `OnUpdate`, `/cine`.
- A piece that shares a file-level local with another piece keeps it on a feature table (`ns.Chat`, `ns.Bars`, `ns.Faders`, `ns.Menu`, `ns.Setup`, `ns.Layout`, `ns.Core`), declared at the top of each file with `local Chat = ns.Chat or {}`. Values that are reassigned live there only; read-only helpers stay local in their own file and are also exported there.
- Call other files through `ns` at run time, not through locals captured at load, so load order only matters for `Cine.lua` being last.
- Comments in English, short, only where the reason is not visible from the code.
